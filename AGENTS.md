# Project rules

## Privacy and publication
- Work locally by default. Never push to GitHub, deploy, publish, or upload files without Yutong's explicit approval.
- Never publish credentials, tokens, passwords, private keys, hidden configuration, private correspondence, or unrelated personal files.
- Use the supplied CV as the source of truth. Include its professional and contact information in the requested local page; ask before making that information or the original CV publicly accessible.
- Do not add tracking, analytics, third-party embeds, or remote assets that disclose visitor information.

## Ask first
- Ask before any GitHub push, public release, hosting deployment, or upload to an external service.
- Ask before deleting or replacing source documents, changing factual CV claims, or exposing additional personal information.
- Do not send messages or contact anyone on Yutong's behalf without explicit instructions.
- Proceed with reversible local edits, previews, and checks within the requested scope.

## Content and style
- Preserve all CV information and its section order. Do not invent achievements, qualifications, or dates.
- Write in clear, concise professional English. Use factual descriptions and the CV's wording where practical.
- Use Columbia blue, dark navy, generous whitespace, and restrained visual accents.
- Keep navigation streamlined, responsive, keyboard accessible, and readable on mobile.
- Use semantic HTML, visible focus states, sufficient contrast, and respect reduced-motion preferences.
- Prefer a self-contained static page with local assets and minimal dependencies.
- Verify content, links, and responsive layout before delivery. Report limitations honestly and list every created file.
